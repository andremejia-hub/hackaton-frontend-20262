## Stack, seguridad de configuración y conservación del trabajo

- React 19, TypeScript strict, Vite, React Router, Tailwind CSS, Fetch, Node v24.19.0 y npm 11.17.0; mismo package.json y package-lock.json que al comenzar esta auditoría, sin dependencias nuevas.
- Revisión de src: sin any explícito, TODO/FIXME de requisitos, URLs HTTP del backend, datos ficticios de producción, librerías prohibidas ni simulación de paginación en cliente. Los enums y etiquetas son los del contrato, no datos del workspace.
- Producción lee VITE_API_BASE_URL y no tiene fallback hardcodeado. .env y credenciales siguen ignorados. La configuración E2E usa un dominio de prueba que se intercepta completamente.
- CP3, CP4 y CP5 y sus endpoints de negocio no fueron implementados ni modificados. El caso UNLOCKED es una respuesta aislada de GET /log-pose en tests para verificar que CP1 representa el estado que recibe, no un desbloqueo real.
- Se preservó el trabajo del compañero: no se cambiaron el JSX, los campos, las validaciones, los mensajes específicos ni la llamada de registro; tampoco FormField, AuthProvider o AuthContext. La lógica adicional de AuthPage se ejecuta únicamente para login.
- Accesibilidad/responsividad preexistentes conservadas; E2E de teclado, foco, landmarks y ausencia de desbordamiento horizontal siguen en la suite.

1. **Con mocks:** los 18 requisitos funcionales de las tablas, incluidos login/token, me, expiración, dashboard, Log Pose, crews, wanted y detalle, errores, latencia y navegación. Las fixtures solo viven en tests y no se importan por la aplicación.

## Limitaciones

- **L1 — API autenticada real:** no revalidada en esta auditoría por falta de sesión existente accesible. La evidencia funcional actual usa mocks y el contrato público real. No se necesitan credenciales para repetir esas pruebas. El cierre con 8/8 y 10/10 está sujeto a esta distinción explícita.
- **L2 — Navegadores:** Chromium desktop y emulación móvil iPhone 13/touch; no Safari real, WebKit, Firefox ni dispositivos físicos. Teclado/roles/foco/viewport comprobados, sin auditoría formal de lector de pantalla.
- **L3 — Entrega académica:** README e integrantes/códigos y hackathon.json con TEAM_CODE oficial siguen requiriendo datos reales no suministrados. No se inventaron ni modificaron. Registro corresponde al compañero y no es tarea pendiente de este alcance.
- **L4 — Fuentes adicionales:** esta auditoría toma el README completo y el contrato como fuentes solicitadas. Projects privados no se han certificado; el informe anterior registraba que el acceso no estaba disponible. Esto no se usa para inventar requisitos adicionales.
- Las advertencias NO_COLOR/FORCE_COLOR provienen de la ejecución de herramientas, no de errores de aplicación. Los comandos con esbuild/Chromium se ejecutaron con permisos aprobados debido a restricciones del sandbox de Windows.
- No se hizo push, despliegue ni cambio de credenciales oficiales.
